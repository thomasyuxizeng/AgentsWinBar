# Native log costs with real prices

Branch `perf/native-costs`, worktree `native-costs`. Nothing is committed. All six changes are in, each with unit
tests, and the three verify commands pass. The parity check was run on the real logs; its table is below.

## Read this first

1. **Codex long-context threshold: the brief and the sources disagree, and the data now says which model uses which.**
   The brief says the threshold is 200K. Upstream at the reviewed commit and models.dev today both say 272K (the
   lane is named `context_over_200k`, but its context tier is 272,000 tokens). The app's ledger shows the installed
   CLI priced `gpt-6.1-sol`, `gpt-6.2-sol` and `gpt-6.2-astra` above 200K and `gpt-6-astra` above 272K (evidence
   table below). I shipped exactly that as data: three per-model `200000` entries in
   `Services/Native/Cost/Pricing/pricing-overlay.json`, every other model on its 272K tier. With one global 200K
   threshold instead, three more Codex days miss (28 Oct, 29 Oct, 4 Nov: 3.3% to 13.7% above the ledger) and 8 Nov
   gets worse. Deleting the three entries follows models.dev: 15 Codex days then land 1.0% to 17.9% below the
   ledger, 13 of which match it now. This is your call; it is one JSON block.
2. **Unpriced share is 0.00% for Codex and 0.74% for Claude, not 0%.** The Claude remainder is two DeepSeek model
   ids used through Claude Code (83,681,937 tokens). The CLI left the same tokens unpriced (null cost in the
   ledger), upstream's rules find no price for them, and models.dev has no single list price (resellers range from
   0 to 2.40 USD per million input tokens). They are counted in the new unpriced-tokens figure. To price them, add
   the two ids to `custom-pricing.json` in the app's data folder.
3. **Parity: Claude 26 of 26 days within 1%; Codex 23 of 27.** The four Codex days are explained below; three of
   them are the native scanner counting requests the CLI did not, with the cause not established.
4. **The app now makes one outbound request a day** to `https://models.dev/api.json` (plain GET, no user data, a
   generic User-Agent) when costs are enabled and the cost source is native.
5. **Not run:** the packaged app itself. Routing, interpretation, the watcher and the service are covered by unit
   tests and the probe, not by launching the tray app.

## Changes

### 1. Real prices
Port of upstream's pricing (CodexBar `CostUsagePricing.swift`, `ModelsDevPricing.swift`,
`CostUsageCustomPricing.swift` at `a26ca57`). Lookup order: the user's `custom-pricing.json`, then rates from
before a published price change, then the models.dev catalog, then upstream's built-in tables. Rules kept in code:
model aliases, long-context selection, Claude cache writes (5-minute rate, one-hour at twice the input rate), Codex
Fast and Ultrafast multipliers. Rates are data.

- `Services/Native/Cost/Pricing/models-dev-prices.json`: bundled snapshot (18 Anthropic, 40 OpenAI models),
  generated by `tools/update-model-prices.ps1` (`-InputPath` accepts a saved `api.json`).
- `Services/Native/Cost/Pricing/pricing-overlay.json`: upstream's built-in and historical tables as data, plus the
  per-model threshold entries from point 1.
- `Services/Native/Cost/CostPriceCatalog.cs` (new): catalog, overlay and custom-pricing parsers. The live 7 MB
  catalog is read as a stream; only the two providers are kept.
- `Services/Native/Cost/CostPriceStore.cs` (new): refresh at most once every 24 hours into `model-prices.json`
  beside `settings.json`. The attempt is recorded before the download, so a failure is not retried until the next
  day. Any failure (offline, non-2xx, not JSON, a catalog without priced Anthropic or OpenAI models, over 64 MB,
  unwritable folder) keeps the current prices. Models that disappear from models.dev keep their last known rate.
- `Services/Native/Cost/CostPricing.cs` (rewritten): the rules above. Other vendors' model ids are now kept by
  name instead of "unknown".
- `Services/Native/Cost/NativeCostScanner.cs`: `ReadReport` prices each bucket and counts unpriced tokens.
- `Models/CostData.cs`: `UnpricedTokens` on `CostDataDto`, `CostData` and `DailyCost`. No XAML reads it yet.
- The two JSON files are embedded resources in `CodexBarWin.csproj`, the test project and `tools/CostProbe`.

Tests: `CostPricingTests` (47), `CostPriceCatalogTests` (15), `CostPriceStoreTests` (19).

### 2. Compressed Codex logs
Upstream does not read `.zst`. It lists only `.jsonl`, in `sessions` and in `archived_sessions`, and uses the
existence of `name.jsonl.zst` only to keep a cached session id alive. That works for upstream because its cache
saw the log before it was compressed; a fresh native index would never see the 780 archives.

Decision: read them. `NativeCostScanner` now accepts `*.jsonl.zst` under Codex roots through **ZstdSharp.Port
0.8.6 (MIT, fully managed)**, and `archived_sessions` is a Codex root. An archive shares the index entry of the
plain log with the same name, so a log that is compressed later is not counted twice: the scanner decompresses it,
skips the bytes already indexed and parses only what was appended before compression. If both files exist the
plain one wins. CPU after the first scan: an unchanged archive is never opened again, and a newly compressed log is
decompressed once (a few milliseconds). Path keys now ignore case.

Files: `Services/Native/Cost/NativeCostScanner.cs`, the three project files (package reference).
Tests: `NativeCostScannerArchiveTests` (15, shared with change 4).

### 3. Cost source setting
`AppSettings.CostSource`: `native` (default) or `wsl`, normalized like the usage sources, set in `settings.json`
(`"costSource": "wsl"`). With `native`, `FetchCostsAsync` calls the new `INativeCostService` once for all due
providers: one index update off the UI thread, then one report per provider serialized to the CLI's JSON and passed
through `InterpretCostResult`. The ledger, the 30-minute cache, last-good handling, the timeout backoff and the
dashboard are unchanged. Gemini gets the same empty reading the CLI returns for it. The index is
`cost-index\index.sqlite` beside `settings.json`. A scan that exceeds the existing cost deadline is reported as a
timeout and continues from where it stopped on the next attempt. With every usage source and the cost source
native, no code path reaches `IWslService`.

Files: `Models/AppSettings.cs`, `Models/UsageSource.cs` (comment), `Services/CodexBarService.cs`,
`Services/Native/NativeCostService.cs` (new), `App.xaml.cs` (registration).
Tests: `CostSourceTests` (14), `CodexBarServiceNativeCostTests` (18), `NativeCostServiceTests` (9).

### 4. Change notifications instead of a listing
`Services/Native/Cost/CostLogWatcher.cs` (new): one `FileSystemWatcher` per root marks changed logs, and new or
renamed directories, as pending. `NativeCostScanner.Update` takes that list and looks only at those paths. A full
listing happens at startup, after lost notifications (buffer overflow, watcher error, a root that could not be
watched or appears later), when more than 2,048 paths are pending, and every 6 hours. A failed update keeps its
work for the next one.

Tests: `CostLogWatcherTests` (13), plus the changed-path cases in `NativeCostScannerArchiveTests`.

### 5. Parity mode in the probe
`tools/CostProbe/Parity.cs` (new), `tools/CostProbe/Program.cs` (dispatch), `tools/CostProbe/CostProbe.csproj`.

```powershell
dotnet build tools/CostProbe/CostProbe.csproj -c Release -nodeReuse:false
& ./tools/CostProbe/bin/Release/net10.0-windows/CostProbe.exe parity 2026-10-26 2026-11-24
```

It indexes the real folders into a temporary index (deleted afterwards), reads the installed app's
`cost-ledger.json` read-only, and prints per-day totals, model ids with totals, and timings. No log line, prompt
or path is printed.

### 6. Tests
150 tests in eight classes, synthetic fixtures only (`CostTestSupport.cs` holds the shared ones).
`CostPricingTests` replaces its three earlier tests.

### Days that miss, and Claude's six token-mismatch days

- **Claude 20 Nov (+336,796,515 tokens, +40.87% USD).** The ledger entry was written at 17:30 on 20 Nov, before the
  day ended, and no Claude scan has succeeded since ("Scan timed out after 20 min" in the app's cost cache). Counting
  only usage up to that time, native has 756,400,588 tokens against the CLI's 756,113,809 (+0.04%) and 273.12 USD
  against 273.05 (+0.03%). The native running total reaches the CLI's figure at 17:29.
- **Claude 27 Oct, 31 Oct, 8 Nov, 16 Nov, 18 Nov (+0.03% to +0.06% tokens, at most +0.05% USD).** Native counts
  slightly more on these five days. Their ledger entries were written after the day ended, so a partial snapshot is
  ruled out. The cause is not established; the candidates are the duplicate-resolution differences the spike lists
  (tie-breaks, scan-window resolution). All five are within the 1% target.
- **Claude 21 to 24 Nov.** The ledger has no day to compare. Native has 155,296,422, 131,002,964, 231,296,723 and
  327,580,436 tokens (56.04, 47.38, 85.07 and 124.81 USD).
- **Codex 2 Nov (+1.93% USD, tokens equal).** 50 `gpt-6.1-terra` requests are recorded with service tier
  "priority". Native prices them at upstream's Fast rate (2x): 2.30 USD. The CLI's 1.89 USD is exactly the Standard
  price. Upstream decides Fast pricing from additional trace evidence that the native parser does not read (see
  limits).
- **Codex 3 Nov (+0.73% tokens, +2.16% USD).** Native counts 662,103 more tokens (207,970 `gpt-6.1-sol`, 454,133
  `gpt-6.1-terra`), and 12 `gpt-6.1-sol` requests carry the "priority" tier. Cause of the extra tokens not
  established.
- **Codex 8 Nov (+5.66% tokens, +7.14% USD).** Native counts 509,249 more `gpt-6-astra` tokens from the day's two
  session files. Cause not established.
- **Codex 10 Nov (+56.01% tokens, +34.67% USD: 0.12 against 0.09).** One session, four requests. The CLI's total equals the
  first three; native also counts the fourth (52,615 tokens). Cause not established.
- **Codex 24 Nov (+70.01% tokens, +144.05% USD for the full day).** The ledger entry was written at 19:03 that day.
  Up to that time native has exactly the CLI's 1,995,013 tokens and 1.24 USD.
- **Codex 30 Oct, 9 Nov, 17 Nov.** No ledger day and no native usage.

For the three Codex days with extra tokens: none of the files is in `archived_sessions` (those are from 3 Oct,
13 Oct and 15 Nov), and the ledger entries were written after the day ended. What remains are the Codex parser
differences the spike lists as unported (request ownership, fork baselines, resetting counters), which this task
did not change.

## Limits and things left as they were

- **Upstream files I could not read.** `api.github.com` timed out for the whole session, so I could not list the
  repository and fetched files by path from raw.githubusercontent.com. I did not find the file that holds
  upstream's model-taking Codex cost function and its priority-trace logic. The lookup order and the Fast rules come
  from `CostUsagePricing.swift` and its comments.
- **Fast tier attribution** is the spike's: the most recent service tier setting in the session. The ledger shows
  the CLI did not price those requests as Fast on 2 Nov.
- **Catalog scope.** Only the `anthropic` and `openai` providers are kept from models.dev. Upstream also consults
  other first-party vendor catalogs for models used through Claude Code; for the two DeepSeek ids in these logs it
  finds no price either.
- **Refresh merge.** Models missing from a new download keep their old rate by exact id. Upstream matches on a
  normalized identity; that part is not ported.
- **Thresholds.** The index keeps two bands per request (over 200K, over 272K), so only those two thresholds are
  exact. `claude-haiku-5-5` has a 100K context tier on models.dev without the long-context lane; upstream ignores
  such tiers and so does this port.
- **Notifications.** A writer that keeps a log open can delay the notification until the data is flushed. The
  6-hour listing is the safety net. This was not measured against live sessions beyond the unit tests.
- **Ledger.** The first native scan records the last 30 days through the existing ledger rules: days with equal
  token coverage are repriced, days with different coverage take the higher value, and Claude's 21 to 24 Nov are
  added. Nothing in `CostLedger.cs` changed.
- **Setup check** is unchanged: it skips WSL when every enabled provider's usage is native. With the cost source
  set to `wsl` and all usage native it still skips, as it did before this change.
- **Index layout.** Path keys changed (case-insensitive, archive shares the plain log's key). No index from this
  code line has shipped, so there is nothing to migrate.
- Not changed: XAML, `SPIKE-native-costscan.md`, `docs/perf/OPTIONS.md`, `CHANGELOG.md`, the probe's original mode.
